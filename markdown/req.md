# 2026-07-30

@html/ofdm.html 和 @script/ofdm-modem-worklet.js 共同实现了一个通过空气声学信道进行OFDM数字通信的网页demo，利用手机、PC的消费级声卡，通过 Web Audio API 实现基于空气信道的单向广播、任意时刻切入接收的实时文本传输。

我的需求场景是空气声学信道下类似于DRM的广播，也就是把突发（长消息）通信和接收机任意时刻切入（冷启动）结合起来。因此，在技术方案上，希望把短（定长）物理帧+独立同步头和散布导频结合起来。请你实现以下3个需求：

1、分帧方法变更。现在的实现是消息有多长，物理帧就有多长，比如消息有n个字符，那么1个物理帧就包含全部的n个字符，前面有1个粗同步前导，其余的就是中间的细同步符号。在这个可能长达几分钟的波形中，只有开头存在唯一一个粗同步前导，其余时间全靠周期性的细同步（训练符号）在苦苦支撑。而我的诉求是：把消息分成定长packet（可能需要padding）之后，每个packet被打包成一个中等长度定长的物理层的帧，包含完整的粗同步头和中间插入的细同步符号，因而一段长消息应该被切分成多个中等长度的packet，再封装为中等长度的物理层帧，逐个发射出去，接收机进而定期执行粗细同步。这样做，可以在不可靠的声学信道中定期重启同步，并适应接收机随时开机切入的需求。

2、增加散布导频机制：在现有的5个符号插入一个细同步符号的“块状导频”的基础上，选取若干子载波作为导频点，形成时频二维散布的导频模式，类似于DRM的做法。

3、增加显式的CFO（载波频偏）补偿。代码中利用训练符号进行了信道估计（包含相位），但没有显式计算和补偿全局的载波频偏 (CFO) 或采样率偏差 (SFO)。如果两台设备的声卡采样率存在 100 ppm 的偏差，随着时间推移，星座图会发生缓慢旋转。虽然每 225ms 重新估计一次信道可以“隐式”吸收一部分相位误差，但在长包传输时可能会导致均衡误差积累。建议: 在粗同步阶段，利用两段相同序列的相位差来计算并补偿小数倍频偏；或者利用导频计算当前的相位旋转角，并对所有数据子载波进行相位补偿。

不要修改无关文件，不要执行任何删除性质的命令。
